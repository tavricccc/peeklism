安裝與需求

選好檔案
按一下空白鍵

Peeklism 是繁體中文的 Windows 11 即時預覽工具。在檔案總管或桌面選取一個項目，按空白鍵，預覽就在原地出現；再按一次收回。

預覽視窗不進入啟動鏈，所以檔案總管從頭到尾沒有失去鍵盤：方向鍵繼續換檔案，預覽跟著換內容。

在這一頁按按看 先看現況

在 GitHub 上讀原始碼

0.6.0 · Windows 11 build 26100 以上 · x64 · WinUI 3 · 早期版本

一個鍵，
而且是那個最大的鍵

要看一眼檔案裡面是什麼，本來得雙擊、等程式載入、看完、再關掉。空白鍵把這四步縮成一步，而且手已經在鍵盤上了（選取檔案用的就是方向鍵）。

預覽視窗不搶焦點

視窗帶著 WS_EX_NOACTIVATE，永遠不進入啟動鏈。檔案總管因此沒有失去鍵盤，方向鍵、重新命名、複製與右鍵選單全部照常運作，預覽只是反映你選到哪一個。換成會搶焦點的做法，就得把方向鍵轉送回去，而轉送會掉鍵。

正在打字的時候，空白鍵還是空白鍵

重新命名檔案、在搜尋框或位址列輸入，視窗類別仍然是檔案總管。這種時候吞掉空白鍵會毀掉使用者正在打的字，所以焦點在文字輸入控制項上時，按鍵直接放行。

換檔案時視窗不動

預覽開著的時候，每 150 毫秒重讀一次選取項目：方向鍵、滑鼠點選，或任何其他來源造成的改變都涵蓋得到。換到新檔案只替換內容，視窗留在原位：在資料夾裡一路按方向鍵時，會跳動與改變大小的預覽是沒辦法用的。

鍵盤 hook 只在需要的時候裝上

只有檔案總管、桌面或開啟檔案對話框在前景時才掛上系統層級的鍵盤 hook，離開就卸下。讓它一直裝著，等於把 Peeklism 放進這台機器上每一次按鍵的必經之路，換不到任何好處。

現況：0.6.0 加入完整查看器

空白鍵維持快速預覽；使用「開啟檔案 → Peeklism」或預覽中的「完整查看」，會開啟獨立的唯讀查看器。支援原始解析度圖片、影音控制、完整 PDF、Markdown 與文字。開啟檔案對話框的預覽和設定介面仍未完成。

從 GitHub Releases 下載

0.6.0 發行頁提供 Peeklism.Setup.exe 與 SHA-256 校驗檔。安裝檔尚未簽章，Windows 可能顯示警告。也可執行 scripts/Publish-Installer.ps1 從原始碼建置。

開啟檔案對話框只做到一半

對話框的偵測已經完成，讀取它選了什麼還沒有：那個視窗屬於別的行程，不會註冊到 shell 視窗集合，必須把原生 DLL 載進對方的執行緒才讀得到。在那之前，對話框上按空白鍵不會有預覽。

三種介面，同一個按鍵

按下空白鍵的那一瞬間，要先知道前景視窗是什麼。這個判斷只看視窗類別名稱，全部是便宜的 user32 查詢，因為它跑在低階鍵盤 hook 的回呼裡，而 Windows 會計時，太慢就直接把 hook 拔掉。讀取選取項目是 COM 呼叫，等離開回呼之後才做。

檔案總管與桌面不需要注入程式碼

Explorer 會把自己的視窗註冊到行程外也看得到的 shell 視窗集合，IShellWindows 直接就能列舉，再從對應的那一個讀出目前選取的項目。「本機」這類虛擬項目回報的是剖析名稱而不是真實路徑，會被排除掉。

對話框則必須進到對方的行程裡

開啟檔案對話框屬於別的行程，而且不會註冊到那個集合，要讀它選了什麼，只能把原生 DLL 載入對方的執行緒。這部分之後由 Peeklism.Native 處理；在那之前，對話框會被正確認出來，但讀不到選取項目。

順帶一提，訊息方塊也是 #32770。只有底下真的掛著 shell 檢視的對話框才算數；在訊息方塊上吞掉空白鍵會是個 bug。

七種內容，
加上一個後備

預覽必須在按下空白鍵之後一兩個影格內出現，所以每一種都是同步而且便宜的：除了開檔以外不等任何 I/O，而且不能丟例外。讀不到的檔案也要有一個預覽，說清楚 Peeklism 知道些什麼。

各種檔案類型的預覽方式
類型怎麼呈現
圖片視窗大小照圖片自己的比例算，寬幅全景不會開在上下留白的高視窗裡。只讀檔頭取得尺寸，不做完整解碼。PNG、JPEG、GIF、BMP、WebP、HEIC、TIFF、AVIF、DNG 等等。
影片MP4、MOV、MKV、AVI、WMV、WebM，自動播放並附播放控制列，預設靜音，因為預覽常常是在安靜的地方打開的。
音訊MP3、M4A、WAV、FLAC、AAC、OGG、Opus，同樣自動播放、預設靜音。
純文字與程式碼等寬字、不換行、可選取，橫向與縱向都能捲動。只讀開頭 256 KB，超過的話在副標註明；預覽不必為了一份幾 GB 的紀錄檔整個讀進來。
Markdown標題、段落、清單、引言、圍籬式程式碼、分隔線、表格與行內強調都會排版。渲染器是手寫的，因為預覽等不起載入一套套件，而且解析不了的內容也必須以純文字照樣看得見。
PDF視窗先開，頁面再一頁一頁補進來。等第一頁算完才開窗，就失去了按空白鍵的意義。最多算前 25 頁，總頁數會寫在最後一行。
資料夾列出裡面的項目，最多 300 筆，並顯示總數。視窗高度跟著列數收斂：幾乎空的資料夾開在一個高視窗裡看起來像壞掉了。
其他認不得的副檔名顯示「XXX 檔案沒有可用的預覽」，仍然有檔名、大小與修改時間。讀不到的檔案顯示的是失敗的原因，不是一個空白視窗。

沒有主視窗，
只有系統匣裡那一個圖示

Peeklism 沒有自己的視窗可以回去，所以系統匣圖示是唯一能暫停或結束它的地方。右鍵選單有四項：暫停預覽、登入 Windows 時啟動、關於，以及結束。

暫停時鍵盤 hook 會被卸下，而不只是忽略按鍵。暫停中的 Peeklism 是真的離開了按鍵的路徑。

開機自啟用的是目前使用者的 Run 登錄機碼，不需要系統管理員權限。Peeklism 只有在執行中才有用——鍵盤 hook 沒裝上之前，空白鍵什麼也不會發生，而一個要先自己去啟動的預覽工具，沒有人會想到要用。

同一個 Windows 登入工作階段只會有一份 Peeklism：兩份就是兩個鍵盤 hook 搶同一個空白鍵。

  • 暫停預覽
  • 登入 Windows 時啟動✓
  • 關於 Peeklism
  • 結束

系統匣右鍵選單的項目（此處為繪製的示意圖）。

一個安裝程式

Peeklism.Setup.exe，一個檔案，旁邊沒有需要一起保留的東西。裡面同時帶著兩種版型與共用執行環境的套件，安裝時自己決定裝哪一種。

兩種安裝版型與各自的需求
裝到機器上的是需要什麼
共用版型機器上登錄一份共用的 Windows App 執行環境，元件已經在安裝程式裡，不需要連網
自帶版型不需共用 Windows App SDK，執行環境放在安裝資料夾裡

共用版型的 WinUI 來自 Windows 集中保管的 MSIX framework package，整台機器只有一份，Downlism 與 Flowlism 指向同一份。預設安裝到 %LocalAppData%\Programs\Peeklism，並自動建立開始功能表捷徑。

不需要系統管理員，也不需要開發人員模式

登錄由 Peeklism.Bootstrap 在安裝介面啟動之前完成——安裝介面自己就是 WinUI，不可能是登錄它自己所需元件的那個東西。套件是微軟簽章的 Store 元件。

拒絕或失敗都不是死路

已經登錄過就直接用共用版型，什麼都不問；沒有才詢問，而使用者回答「否」、或機器根本不允許登錄共用元件時，改裝自帶版型繼續走完。

舊版升級會自動換版型

舊的自帶版型升級到共用版型時，安裝紀錄裡不再存在的檔案會被移除。這是必要的：Microsoft.UI.Xaml.dll 留在執行檔旁邊的載入順序，高於共用套件。

Windows 11 build 26100 以上、x64

.NET 10 與 Windows App SDK 由安裝程式處理。PDF／文件另外需要 Microsoft Edge WebView2 Runtime，部分影音格式需要 Windows 解碼器。自己建置需要 .NET 10 SDK，執行安裝程式腳本需要 PowerShell 7（pwsh）；Windows PowerShell 5.1 缺少它用到的 API。想先看看偵測那一層在做什麼，可以執行 dotnet run --project tools/Peeklism.Probe，切到檔案總管點選檔案，每次變化都會印出一行。
